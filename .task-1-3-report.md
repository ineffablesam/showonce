## Review remediation

Status: **DONE**

Added test-first regressions and fixes for all 11 Critical/Important findings:

- command-specific event allowlists prevent recipient-specific value leakage;
- confirmation tokens and event IDs use independent generators, and tokens never enter semantic events;
- typed, runtime-validated helper decisions flow through `executeCommand()` before repository persistence;
- preference commands are key/value discriminated unions with runtime rejection;
- selected-plan events record only authoritative catalog prices;
- registrations are filtered to active route scope while `SHOWONCE_TOOLS` remains global;
- `useWebMCP` creates and passes an abort signal immediately in its effect, aborts pending registration on cleanup, and depends on stable context members rather than the context object;
- all started invocations audit terminal `read`, `applied`, `refused`, `aborted`, or `error` outcomes;
- preference JSON Schema uses key-specific `oneOf` branches;
- handoff decoding validates exact top-level and nested procedure/step/command shapes and rejects additional or sensitive fields;
- BroadcastChannel creation is browser-only and repositories expose `dispose()` to close it.
