# ShowOnce Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a polished, resettable ShowOnce product whose complete benefits-renewal handoff works through shared semantic commands and real client-side WebMCP tools.

> Historical plan: persistence details here were superseded by
> `2026-09-02-cross-device-supabase-vercel.md`.

**Architecture:** A strict, framework-independent domain core powers both human UI and WebMCP entry points. TanStack Start routes consume repository interfaces through TanStack Query; shared resources now use capability-guarded Supabase RPCs and token-only URLs, with local storage limited to demo state. Route-scoped WebMCP registration is feature-detected and auditable.

**Tech Stack:** React, TypeScript strict mode, TanStack Start, TanStack Router, TanStack Query, TanStack Form, TanStack Table, Tailwind CSS, Vite, webmcp-types, Vitest.

## Global Constraints

- Never fake WebMCP when unavailable.
- Register tools client-side with `document.modelContext.registerTool(...)`.
- Every human and WebMCP mutation goes through `executeCommand()`.
- Never serialize credentials, session data, selectors, coordinates, screenshots, or recipient-specific values.
- Final submission requires recipient confirmation valid for 120 seconds.
- No mandatory API keys or backend.
- P0 critical flow must work before visual extras.
