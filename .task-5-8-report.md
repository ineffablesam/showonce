## Review remediation addendum — 2026-09-02

This addendum supersedes the earlier six-action and demo-limitation notes above.
All Critical and Important review findings were remediated end to end.

### Behavior corrected

- Samuel now completes seven ordered semantic actions before Finish is enabled:
  annual, paperless, Gold, recipient-detail review, preview, 120-second human
  confirmation, and successful submit. Seed counts are Samuel 1 and Mom 2.
- Procedure compilation preserves sanitized recipient-detail, state-check,
  confirmation, and submit steps. Recipient address/dependent preservation now
  comes from deterministic comparison against the persisted Mom account.
- Handoff links contain an `encodeHandoff` payload; `/s/$handoffId` decodes it
  when sender storage is absent, validates its sanitized schema and expiration,
  and uses the persisted recipient account.
- WebMCP cannot create confirmation. The UI creates ephemeral confirmation;
  submit is a separate action, refuses before confirmation, succeeds afterward,
  and returns `confirmation_expired` after 120 seconds.
- Domain plan-selection guards refuse WebMCP material increases and unavailable
  substitutions without a matching human/helper authorization.
- Recipient workflow phase, result, selected plan, and helper request ID persist
  in a run repository. Query caches update from actual command/tool outcomes.
- Helper reload resumes the same request and requires an explicit Silver or
  Premium recommendation, or “Let Mom decide”; the exact decision synchronizes
  through repository/BroadcastChannel.
- Recipient routes register exactly the ten requested focused tools. There is no
  confirmation-creation or generic plan-selection tool.
- WebMCP inspector activity polls every second and browser `getTools()` every
  two seconds when available.
- Handoff creation now includes Mom, optional note, seven-day expiration, safe
  preference permission, confirmation requirement, and helper escalation.
- All tables use TanStack Table v9 `useTable` with explicit feature composition;
  no `useLegacyTable` imports remain.
- New ShowOnce now captures task name, optional description, and the fixed Nexa
  Benefits Demo target; the ignored walkthrough-type choice was removed.
- Mobile navigation exposes `aria-expanded`/`aria-controls`, traps focus, closes
  with Escape, returns focus, and has keyboard-visible radio/checkbox focus.
- Registering, error, unavailable, and ready WebMCP states remain distinct.
